# 语言条件下的功能性抓取与手内重抓

目标是完成“随机摆放 → 抓取 → 手内或双手辅助重抓 → 功能性握持 → 实际使用”。
当前新增的是离线判定器和示例契约，尚无闭环策略、实测接触采集或成功轨迹；不增加已完成场景数。

## 已有基础与缺口

|能力|已有证据|尚需实现|
|---|---|---|
|机器人与场景|54 自由度双臂双手、五路相机、10 基础任务、72 扩展原型、1 毛巾入口|关节/碰撞/触觉在实际 Isaac 版本下验证|
|物体姿态|世界系初始/目标位姿，抬升与接触代理判定|掌心系功能位姿集合、功能部位与接触区域标注|
|控制|关节目标回放、部分手臂 IK|指级重抓策略、双手交接、失败恢复|
|语言|任务标题|同物体不同用途指令、训练/测试分离的释义、语言反事实对照|
|物理成功|尚无当前版本端到端成功证据|真实接触点、作用部位交互、功能结果及持续稳定性|

## 评测协议

1. 初始分布需限定在可达、无穿透的桌面区域。随机平移、稳定放置面和朝向，先自由落下静置；拒绝不合法状态并记录拒绝率。不能承诺任意空间摆放都可解。
2. 在物体局部坐标标注握持区、工作区、禁触区、功能轴及一个或多个有效掌心相对位姿。每个用途分别标注，不能把所有用途压缩为同一个世界系目标。
3. 固定主手标识，计算 `T_palm_object = inverse(T_world_palm) @ T_world_object`。主手变化应单列交接阶段，不能通过切换坐标系伪造手内旋转。
4. 设置固定腕与自由腕两条赛道。前者只在手内调整阶段限制腕部运动；后者允许手臂配合，但仍要求手物相对运动与手指动作、接触变化共同成立。正常执行工具用途时允许手臂运动。
5. 单手、双手辅助、桌面辅助分开统计。当前判定器覆盖前两种离桌赛道，双手辅助期间至少一只手保持接触；桌面辅助需要另设契约。
6. 顺序判定抓起、重抓、功能位姿、使用结果。勺子需要实际物料转移；剪刀需要切断；钥匙需要插入并转动；手机需要按指令完成画面/输入事件。到达一个姿态不能代替这些结果。
7. 保留初始姿态、动作、每物理步的实际手/物位姿、成对接触位置/力、物料状态、失败原因、版本及输入哈希。禁止通过物体瞬移、吸附、布料顶点驱动产生正式成功。

## 本次实现

`evaluator.py` 实现掌心系位姿、连续抓持、离桌约束、固定腕预算、指关节变化、接触刚体集合变化、握持区域、功能结果增量及保持时间判定。世界系刚体旋转不构成手内调整；进入功能姿态之前已有的结果不会被计为新完成。

这是一种保守的离散重抓判定：尚不覆盖接触刚体集合不变的连续滚动。后续应增加接触斑点迁移和相对运动的一致性检测。接触数量不等于力闭合，成功自然度仍需轨迹平滑性、能耗、关节裕量、工具使用质量和人类盲评补充。

`example_contract.json` 只是勺子转移任务的接口示例。位姿与阈值尚未经机器人运动学和物理标定，不能直接作为正式场景。

```bash
cd /data/benchmark
python -B -m unittest discover -s tests -p test_functional.py -v
python -B -m functional.evaluate_trace functional/example_contract.json TRACE.json --output REPORT.json
```

轨迹格式为 `{"task": "spoon_transfer_contract_example", "samples": [{"dt_s": 0.0041666667, "observation": ...}]}`。
观测字段见 `tests/test_functional.py`；测试观测完全是合成数据。命令只输出 `OFFLINE_TRACE_ONLY`，不会认证物理成功。

## 建设顺序

先标定勺子握柄与手机翻转两个低复杂度任务，接入实际掌心位姿和物体/手接触点，完成固定腕反例测试；再加勺子物料转移、手机按键等功能结果。随后实现双手辅助和钥匙/剪刀等关节或接触复杂任务。

保留 arm-only、直接抓到功能姿态、单手重抓、双手辅助、无语言与正确语言等对照。直接抓对是完整任务的有效策略，应单独报告；需要评测重抓能力时另设初抓非功能姿态的子集。

物体几何、初始摆放与语言模板分别划分开发/封存集，固定种子与相同试验预算。报告端到端成功率和各阶段条件成功率、接触中断、掉落、腕部位移、主手相对旋转、重抓次数与功能质量，并提供多种子置信区间。RSI_DEX 的训练诊断物体不能自动当成本 benchmark 的封存测试集。
